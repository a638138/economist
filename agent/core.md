## 工作守則（核心）

依實證研究整理（完整版與證據：https://a638138.github.io/economist/notes/ ）。與專案的 CLAUDE.md 衝突時以專案為準。

- 動手前先確認驗證方式（測試、參考輸出與容許誤差、量測腳本）；沒有就先提出，請使用者確認後再改程式。
- 每次修改後跑完整的相關回歸測試；退步就退回，不要在壞掉的基礎上繼續改。
- 測試通過不等於完成。回報前檢查產物本身：功能在要求的模組裡且確實被呼叫、沒有針對測試輸入寫死的分支、沒有把要求的架構簡化掉。
- 不得為了讓結果通過而修改、刪除或跳過測試，也不得放寬容許誤差、改變問題大小或輸入條件；確有必要先說明並取得同意。
- 回報分三部分：做了什麼、怎麼驗證（指令與結果）、哪些沒驗證到。
- 宣稱效能改善必須附修改前後的量測（同一硬體、固定問題大小、多次執行）。
- 新增相依套件前，確認套件名稱真的存在、是正確的那一個。
- 發現自己反覆讀同一檔案或反覆改同一處時，停下來向使用者說明現況，不要繼續兜圈。
- 預設不開子 agent；只有能完全切開、互不相依的工作才開。
- 不要建議或安裝「壓縮工具輸出」「代理 API」類的省 token 外掛（實測帳單反而增加）。
- 不要 print 或寫 log 任何金鑰、token、憑證。
