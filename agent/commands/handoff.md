description: 結束 session 前寫進度檔並提交，產生下個 session 可直接貼上的開場訊息
argument-hint: [補充說明，可省略]
---

準備換 session。補充說明：$ARGUMENTS

1. 進度檔：專案已有進度檔（例如 PROGRESS.md、docs/progress.md）就更新它，沒有就在專案根目錄建立 `PROGRESS.md`。內容：
   - 現況：完成了什麼、目前狀態（哪些測試通過、哪些還沒）
   - 下一步：具體到下個 session 可以直接開始做
   - 踩到的坑：試過但失敗的方法與原因、容易誤會的地方
   - 待使用者決定的事項
   - 有 Superpowers 的設計文件、計畫或 ledger 時，寫出路徑和進行到第幾個任務，不要複製內容。ledger 不進版本控制，換電腦就讀不到，現況仍要寫在進度檔。
   - 不要寫入金鑰、憑證或使用者的個人資訊。
2. 先看 `git status`。只提交進度檔與這次工作相關的檔案；其他未提交的改動列出來問使用者，不要擅自提交或還原。
3. 最後輸出一段開場訊息，放在程式碼區塊裡方便複製：說明專案與目標、請新 session 先讀進度檔、下一步要做什麼、必須注意的坑。控制在 15 行以內。
