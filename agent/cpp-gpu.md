## C++／GPU／即時系統守則

依實證研究整理（證據：https://a638138.github.io/economist/notes/ 「AI Agent 研究（四）」）。

- 平行化（OpenMP、執行緒、搬到 GPU）前先量該段的執行時間；只有幾毫秒以下的段落，開銷可能大於收益，量過再決定。
- CUDA／GPU 改寫每次都要編譯、執行並與參考輸出比對；未經執行驗證的 CUDA 改寫大多是錯的。
- 確認主要運算真的在 GPU 上，沒有留在 CPU；用 compute-sanitizer 等工具檢查同步與競態。
- 移植已為 CPU 手調過（SIMD intrinsics、分塊、預先打包）的程式到 GPU：先嘗試直接轉；若一再失敗，先寫一個乾淨、未最佳化、結果一致的參考版本，再從它轉。
- 即時路徑的時序與同步錯誤，一般測試抓不到；改到這類程式時，提出壓力測試或 sanitizer 檢查。
- 修改 CMake／Makefile 或跨檔案介面時，明確列出改動，交給使用者把關。
