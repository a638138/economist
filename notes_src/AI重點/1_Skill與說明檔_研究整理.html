AI Agent 研究（一）：Skill 與說明檔

整理日期：2026 年 11 月 2 日 · 18 篇參考文獻 · 全文查核版
一句話總結：skill 和說明檔平均有幫助，但很不穩定。人工寫、少而精、註明適用條件的才有效；讓模型自己產生的 skill 或說明檔多半沒用甚至扣分，而且公開 skill 約四分之一有安全漏洞。
收錄門檻：每篇論文都讀過全文，對照內文與表格核對數字，並檢查樣本數、重複次數、統計檢定與作者自述的限制；方法沒有重大問題才收錄，預印本照收但標明。句尾標籤是出處；「對你的意義」是整理者的判斷，不是論文結論。刪除的研究與原因見「AI Agent 研究（五）」。

一Skill 有沒有用：平均有幫助，但很不穩定

  1. 人工寫的 skill 平均有效：87 個任務、18 組模型與 harness、每格 3 次，加上人工 skill 後通過率從 33.9% 提升到 50.5%（+16.6 個百分點）。軟體工程類 +11.6 個百分點，各領域介於 +9.7 到 +28.8。SkillsBench 2026
  2. 有些任務反而變差：87 個任務中有 13 個加了 skill 後變差。SkillsBench 2026
  3. 讓模型自己寫 skill 反而扣分：三組專用 harness 上，自生成 skill 比不用 skill 低 8.1 到 11.5 個百分點。SkillsBench 2026
  4. 真實情境下效益大幅縮水：當 agent 要從 34,198 個真實 skill 中自己檢索，Claude Opus 4.6 的增益從強制載入時的約 20 個百分點降到約 3 個；Kimi 與 Qwen 甚至低於不用 skill。每種設定跑 3 次，沒有信賴區間。Skills in the Wild 2026
  5. 針對任務改寫 skill 能救回一部分：Terminal-Bench 2.0 上，Claude Opus 4.6 從無 skill 的 57.7% 提升到 65.5%，但單靠檢索只有 61.4%，提升主要來自「針對該任務改寫」這一步，而且每題要多跑一次探索。Skills in the Wild 2026
  6. 軟體工程 skill 大多沒差：49 個公開的軟體工程 skill、約 565 個真實 repo 任務，39 個零提升，平均 +1.2%；token 用量從 −78% 到 +451%；7 個專門 skill 最高 +30%；3 個因版本不符最多 −10%。SWE-Skills-Bench 2026
  7. 同一個 skill 換模型就可能變差：9 組配置平均都提升（+4.6 到 +19.5 個百分點），但 36.78% 的任務在某些配置變好、在另一些變差。Downstream Utility 2026
  8. 模型做不來 skill 推薦的方法時，表現低於無 skill：排考程任務中 skill 推薦整數規劃，DeepSeek 搭 Codex 不用 skill 時 3 次全過，用了 skill 3 次全部逾時；GPT 用同一組 skill，求解器失敗後改用允許的啟發式方法，3 次全過。Downstream Utility 2026
  9. 強模型從 skill 得到的增益較大：三種 harness 下 GPT 的增益都比 Qwen 多 3.45 到 8.43 個百分點。只比較兩個模型，不宜當成普遍規律。Downstream Utility 2026
  10. 「有載入」不等於「有照做」：79 個 skill、177 個任務、8 個模型、2 種 harness，最佳綜合分數只有 0.613（GPT-5.5 搭 Claude Code）。觸發率 97% 的配置，照做程度仍只有 0.625；綜合分數低於約 0.5 時，任務表現就低於不用 skill。Skill-Use 2026

對你的意義

skill 值得用在「agent 自己查不到、而且你反覆在做」的流程，例如 SDK 的特定呼叫順序或量測步驟。通用的程式寫法 skill 多半沒效益。新增 skill 後，用幾個真實任務比較有無 skill 的結果，再決定要不要留。

二SKILL.md 怎麼寫

  1. 真實世界的 skill 幾乎都有缺陷：超過 99% 至少有一種「skill smell」，平均每個 10.5 種。最常見的是沒防止 agent 合理化跳過步驟（94%）、關鍵警告埋在內文（81%）、沒有規劃階段（78%）、沒有驗證步驟（69%）；smell 出現後幾乎不會被修掉。Anatomy to Smells 2026
  2. 少量、精簡最好：一次給 2～3 個 skill 增益 +19.0 個百分點，4 個以上只有 +10.1；精簡型 +19.0、標準型 +21.5、詳細型 +14.5，寫成完整文件的只有 +0.7。這是兩組不同的比較（數量、複雜度），不能直接相比。SkillsBench 2026
  3. skill 造成的失敗，多半不是選錯 skill：307 個由 skill 造成的失敗（125 個功能失敗、182 個效率退化）中，skill 的描述誤導只佔功能失敗的 1.6%；68.8% 是 agent 照 skill 做了卻漏掉或填錯任務要求，包括把範例或預設值當成規則；19.2% 把產出放到和任務指定不同的位置。效率退化有 62.6% 來自流程過重，其中過度驗證最多。只測一個模型、一種 harness，標註沒有報告評分者一致性。Agent Skills Can Be Harmful 2026
  4. context 膨脹來自內文：46 個 context 負擔案例中，43 個來自每次都載入的 skill 內文。Agent Skills Can Be Harmful 2026
  5. 壓縮 skill 不太會傷品質：600 個 skill 平均把描述壓縮 48%、內文壓縮 39%，壓縮後分數 0.742 對原版 0.722（p = 0.002，但效果量很小，d = 0.107）；86% 的 skill 壓縮後不低於原版。評分標準同時也是優化目標，數字可能偏樂觀。SkillReducer 2026
  6. 內文多是不必要的內容：抽樣 90 個 skill，只有 38.5% 的條目是核心規則。SkillReducer 2026
  7. 多個 skill 協作時，寫出依賴關係：寫成產物依賴圖（Dependency DAG）比不給組織指示高 6.5 到 11.4 個百分點，也勝過只寫順序。Downstream Utility 2026
  8. 「相關」不等於「有用」：改用「是否支援任務需要的基本操作」排序候選 skill，第一選擇的通過率提升 4.35 到 5.80 個百分點。Downstream Utility 2026

對你的意義

寫 SKILL.md 的檢查清單：關鍵警告放最前面；明寫「不可跳過」的步驟與驗證方式；範例標明「僅供參考，以任務要求為準」；註明適用的 SDK 版本與環境；內文只放核心規則，細節拆到需要時才讀的附檔；驗證寫一次就好，不要要求反覆檢查。

三CLAUDE.md／AGENTS.md：只寫 agent 查不到的事

  1. 讓 LLM 自動產生的說明檔沒幫助，還更貴：4 組 agent 與模型、138 個附說明檔的任務加 SWE-bench Lite 300 題。自動產生的說明檔讓成功率變化 −0.5% 到 −2%（不顯著），步數多 2.45 到 3.92 步，成本增加約 20% 到 23%（顯著）。Evaluating AGENTS.md 2026
  2. 開發者自己寫的說明檔略有幫助，但不顯著：比沒有說明檔平均 +2.4%（p = 0.21），比自動產生的好（p = 0.038），成本仍增加最多 19%。Evaluating AGENTS.md 2026
  3. agent 確實會照說明檔做事：說明檔提到 uv，每題平均用 1.6 次，沒提到時幾乎不用；提到的 repo 專屬工具每題用約 2.5 次。成本增加正是因為它多跑測試、多讀檔。Evaluating AGENTS.md 2026
  4. 說明檔能縮短時間，但沒測正確性：10 個 repo、124 個小型 PR，Codex 加上 AGENTS.md 後執行時間中位數 −28.6%、輸出 token 中位數 −16.6%（都顯著），總 token 沒有顯著差異。每題只跑一次，正確性只抽 50 題做基本檢查。Lulla 等 2026
  5. 小規模實驗看不出差別：17 個真實任務、2 個 agent、每種設定 3 次，「不給說明檔、每次都給、需要時才查」三種做法的通過率沒有顯著差異。作者指出這個規模只能偵測 30 個百分點以上的差距。Khatri 2026
  6. 大家都在寫什麼：2,303 個說明檔中，測試（75.9%）、實作細節（70.8%）、架構（68.1%）最常見；安全只有 14.8%、效能只有 14.5%。檔案中位數 335 到 535 字，大多持續增加內容、很少刪減。Agent READMEs 2025
  7. 指令越多，越容易漏：在「報告中包含指定關鍵字」的人工任務上，最強模型在 500 條指令時只做到 68.9%；靠後的指令較常被忽略，錯誤以完全漏掉為主。這是人工設計的關鍵字任務，不等於真實程式指令。IFScale 2025
  8. 對話被壓縮後，規則會消失：只在對話中講過的規則，長對話被壓縮摘要後，7 個模型合計有 30% 的機率違反（最高 59%），完整保留對話時是 0%。在 3 個模型、5 個軟性規則任務上，規則放在系統訊息時違規增加 0 個百分點，放在使用者訊息時增加 50 個百分點。五模型重複實驗：違規增加 37 個百分點（95% 信賴區間 31 到 43）。Chen 2026

對你的意義

CLAUDE.md 只寫 README 沒有、agent 自己查不到的事：建置與測試指令、SDK 的硬體限制、即時執行緒不可配置記憶體這類規則。不要用 /init 自動產生後直接留用。重要規則寫進 CLAUDE.md，不要只在對話中說，因為長對話壓縮後可能被丟掉。

四Skill 與套件的安全風險

  1. 約四分之一的公開 skill 有漏洞：31,132 個 skill 中 26.1% 至少有一個漏洞（作者估計真實範圍 23% 到 30%）；附帶腳本的 skill 有漏洞的機率是純指令型的 2.12 倍。偵測工具在 200 個人工標註樣本上精確率 86.7%、召回率 82.5%。Skills in the Wild 安全 2026
  2. 憑證最常從輸出外洩：17,022 個 skill 中 3.1% 有憑證外洩問題；73.5% 的漏洞來自把憑證 print 或寫進 log，而 agent 會把這些輸出讀進 context。經實際執行確認，89.6% 可在不提權的情況下利用。Chen 等 2026
  3. 確實有惡意 skill：98,380 個 skill 中確認 157 個惡意（0.16%），70.1% 是竊取資料型；其中 54.1% 來自同一個發布者。揭露後全部下架。作者指出 157 是下限。Malicious Agent Skills 2026
  4. AI 仍會推薦不存在的套件：2026 年 5 個模型、約 20 萬次生成，推薦不存在套件的比例 4.62% 到 6.10%；5 個模型都會幻覺出的 127 個名稱中，53 個仍可被搶註。單一作者的預印本，未測 agent 情境。Churilov 2026

對你的意義

不要直接裝來路不明的 skill，尤其附腳本的；裝之前先讀過腳本。自己寫的 skill 不要 print 金鑰。agent 建議新增的相依套件，先確認名稱真的存在、是你要的那個。
